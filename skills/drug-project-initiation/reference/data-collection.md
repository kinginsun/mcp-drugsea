# 采数细则与库陷阱

本文件只记录**会静默返回错误结果**的行为。库/字段的完整清单查 `skills/drugsea/`。
PubChem 化学/结构式见 [pubchem.md](pubchem.md)。

## 通用陷阱

| 陷阱 | 后果 | 应对 |
|---|---|---|
| 未知字段键被静默丢弃 | 过滤条件消失，返回整库，看起来像「命中很多」 | 每次加筛选后确认 `total` 下降；不降就是键名错了 |
| `global_search` 的国别计数字段恒为 0 | 误判「境外无上市」 | 该字段不可信，一律改由 `product_us` / `product_eu` / `product_jp` 分库确认 |
| 仅有年份的日期被物化成 `YYYY-01-01` | 误读成「1 月 1 日当天事件」 | 见到整批 `01-01` 先怀疑是按年占位，报告里照录并注明 |
| 商品名查不到 | `drug_name=优乐思` 返回 0 | 商品名在 `brand_name` 字段，不被 `drug_name` 匹配 |
| 分面（facet）有独立日配额 | 中途开始报配额错误 | 优先用一次 facet 拿全分布，别逐值试探 |
| 中文名查 PubChem 无 CID | M0 整块缺失 | 改用英文 INN 或 `--cid`；不要用 AI 补结构式 |

## 按库

### `reg_cn`（注册审评）
- 默认 `rows_excluded=1`（排除备案）、`search_mode=1`（关联匹配）。
- 用分面拿 注册分类 / 研发状态 / 办理状态 / 剂型 四个维度，比逐条读快且可直接进表。
- 「潜在首仿」是受理记录上的标记，逐条核对，不要按受理日期自行推断谁是首仿。

### `product_cn`（中国上市）
- 默认 `search_mode=3`。
- **医保、目录集字段滞后**：`is_orange_book`、医保标记常与 `yibao`/`nhsa_code` 矛盾，以专库为准。

### `zldj` / `zlsm`（专利登记 / 声明）
- `zldj` 一条专利可登记多种权利类型（化合物、组合物、用途），到期日可能分别列示，逐项读。
- `zlsm` 要按「针对哪件专利」分组统计声明类型，不要只看总条数。
- `nmpa_reg_patent` 常为 0 条，意味着**无法交叉验证** `zldj`，必须写入数据局限。
- 到期日以公示为准，但公示不含专利权期限补偿与同族分案——在报告里明确声明未核查，
  并要求由知识产权部门出正式 FTO 意见。

### `zhaobiao`（招标挂网）
- `custom` 路由，前端 `/zhaobiao`，接口 `/es/zhaobiao/list`。
- 检索字段只有 `drug_name` / `company` / `province`；**没有 facet 工具**，分布靠取回后自行统计。
- 仅筛选用字段：`notice_year`、`execute_status`、`bid_type`、`province`、`category`、`unit`、`min_unit`。
- **限流是按页面计的日配额**，报错 `code 1006`（「您今日已达当前页面最大访问量」）时，
  其他库仍可正常查。不要因此判定「无挂网数据」，如实记录为当日不可得并稍后重试。
- 价格字段可能是非数字：`国谈药品`、`*`、`未公示`。照录，不要当成缺失或强转 0。
- 统计口径：区分「记录条数」与「省份数」；同省多条属正常（新增挂网/省标/价格调整分别成条）。

### `drugsales`（全终端销售，境外）
- 需 VIP `groupid=205`（自动注入），**必须带 `year`** 加一个药品键，否则查不出来。
- 一年通常 10 条左右，按 `sales_channel`（医院端/零售端）× `strength` × `per_package` 拆分。
- 汇总时用 `sales_amount_usd` 求和，并**自行核验合计**；规格标识可能出现 `500Y` 这类
  与 mg 规格无明确对应关系的原值，照录并注明。
- 渠道结构（零售 vs 医院占比）和规格贡献占比是最有价值的两个派生指标，能直接支撑
  「该做哪个规格」的结论。

### `sales_cn`（国内医院销售）
- 只接受 `drug_name` / `company` / `product`，**不要用 `item`**。
- 新上市品种通常 0 条。这是样本期不足，不是无需求——必须显式写明这一区分。

### `jicai`（集采）
- 查**同类老药**（如非布司他）拿价格天花板，这是 P3 竞争窗口打分的核心依据。
- 命中数常含大量省级带量采购，别当成国采批次数。引用时写清省份与年份。

### 临床库
- `ct_cn` 的 BE 申办方数量通常**远多于** `reg_cn` 里已进审评的企业数。真实排队规模按
  `ct_cn` 估，只按 `reg_cn` 会低估竞争。
- 看最新几条登记的公示日期：若在专利到期前仍持续新增，说明队列还在扩大而非收敛。

## 采数完成前的检查

- [ ] 每个模块都有结论或明确的「不可得」标注
- [ ] 所有 0 条结果都已归入数据局限清单
- [ ] 库间冲突已识别并选定口径（写明理由）
- [ ] 关键数字（专利到期日、挂网价、销售合计）已二次核对
- [ ] 派生指标（片价 = 盒价 ÷ 片数、同比、占比）已手算验证
